# AI Token-应用编排平台

[[AI Token 业务]]知识库模块 17，覆盖 Dify、Coze（扣子）、FastGPT、n8n、RAGFlow。这是企业客户的主要形态：单客户量大、决策链长、粘性极高。前面几层（[[AI Token-桌面客户端]]、[[AI Token-编程Agent]]）的客户是"人在用 AI"，这一层不同——客户是"业务在用 AI"：一个平台后面可能挂着几十条业务流程（客服工单分类、合同条款提取、内部知识问答等），一旦上线就成为业务的一部分，每天自动运行，不依赖某个人是否打开某个软件。

这带来三个对我们极其有利的特性：用量稳定且可预测（消耗跟随业务量而非人的心情，可以做容量规划、授信额度、年度框架协议）；粘性极高（换供应商意味着在几十个应用里逐个改配置、重新测试，几乎没人主动做）；天然需要企业级能力（部门归集、成本分摊、审计日志、发票、合规材料，这正是我们区别于野生中转站的地方，见 [[AI Token-供给体系与产品架构]]、[[AI Token-合规与风险控制]]）。代价是销售周期长（4–12 周），但按 [[AI Token-定价体系与单位经济模型]] 的测算，这是唯一能稳定产生健康贡献毛利的客户类型。

## Dify

企业级 LLM 应用开发平台，这一层里综合能力最强、企业采用最广的开源项目，定位是"可扩展的 AI 产品底座"——既能做 RAG 知识库，也能做工作流编排、Agent 编排、提示词管理，支持本地 Docker 私有化部署。

四类应用形态的消耗特征差异极大：对话型+知识库（输入输出比可达 20:1 到 50:1，缓存优化黄金地带）、工作流型（一次触发多次调用，随节点数线性放大）、Agent 型（带循环，消耗最不可预测，原理同 [[AI Token-编程Agent]]）。一个企业客户的 Dify 上跑着二十个应用，往往两三个占了 80% 的消耗，找出并优化它们是最直接的价值证明。

接入走 OpenAI-API-compatible 供应商类型，需要分别配置对话模型（LLM）、Embedding 模型、Rerank 模型——很多中转服务不支持 Embedding，这是可以主动展示的差异点。Dify 支持按应用级别指定不同供应商，客户可以逐个应用切换，先跑一周看稳定性和账单再决定，这正是"先跑 5%"话术（见 [[AI Token-销售方法论与话术库]]）的完美落地场景。切入点包括成本归因（按应用维度拆分账单）、Embedding/Rerank 完整支持、模型选型咨询（毛利率可达 50%–70%）、私有化部署的合规配套。

## Coze（扣子）

字节系低代码 AI Agent 开发平台，主打拖拽式操作，学习曲线最低，插件生态达万级，以 SaaS 形态为主——这意味着 SaaS 版本我们卖不进去，用户用的是平台自带模型额度。

但它有两个价值：一是最好的"AI 意识启蒙"指标（企业有人用 Coze 搭东西，说明已开始尝试 AI 应用，只是还在轻量阶段）；二是开源版本（Coze Studio 一类）支持私有化部署和自定义模型接入，企业从"试试看"转向"要正式上线、数据不能出去"阶段时，这个转折点就是我们的介入时机。注意不要贬低 Coze 在验证阶段的价值，且要先问清客户用的是 SaaS 版还是开源版，两者能力差异较大。

## FastGPT

企业知识库问答系统，定位比 Dify 更聚焦——专注 RAG，不做太多编排，轻量级部署，学习成本更低，支持本地 Docker 私有化部署（配置在 config.json 与环境变量中）。

典型 RAG 消耗结构：输入极大、输出较小，且比 Dify 更纯粹——几乎所有请求都是"大段检索内容+短问题→短回答"，因此 FastGPT 客户的缓存优化空间是这一层里最大的。技术支持提示：config.json 模型配置文件格式在不同版本间有变化，接入前要先确认客户版本。这是模块 09（[[AI Token-运营SOP与客户成功]]）里"最容易做出首月优化成绩"的客户类型，适合打造为标杆案例。

## n8n

自动化工作流平台，本质不是 AI 产品——它是通用流程自动化工具，有 400 多个应用集成能力，AI 只是众多节点中的一类，支持本地 Docker 部署。

代表一类特殊场景：AI 被嵌进非 AI 的业务流程里（比如新订单→模型判断风险→写入 CRM→发通知），AI 只是一个环节，但会随业务量自动触发、一天可能跑几万次。特点是单次很小、频次极高、完全跟随业务量，可预测性在这一层里最好，最适合容量规划和年度框架协议。风险也在这里——流程一旦配错（如循环触发）可能无人察觉地疯狂调用，n8n 客户是最需要配异常调用告警的一类。接入可走 OpenAI 节点（凭据里设自定义 base_url 与 Key）或通用 HTTP Request 节点。凭据是全局的、可被多条工作流复用，建议客户按业务线创建不同凭据并绑定不同子账号，便于账单拆分。

## RAGFlow

企业级文档理解引擎，特长是处理复杂格式（图表、公式、扫描件、复杂排版 PDF），定位比 FastGPT 更"重"，学习曲线更陡，支持分布式部署。

客户群往往是文档密集型的高价值行业：金融、法律、医疗、科研、制造业技术文档管理。三个特征：文档量巨大导致 token 消耗高；对准确性要求极高，愿意用贵的模型；数据合规要求最严格（法律合同、病历、财务报表都不能随便出域）。因此这是最需要私有化部署方案的客户群（网关组件部署在客户侧，仅出站调用经过我们的通道，见 [[AI Token-供给体系与产品架构]]）。切入点应从合规切入而非价格——第一道门槛是"数据能不能保证不留存、有没有资质、能不能过审计"，必备材料包括资质证明、模型备案文件、数据安全说明、日志留存与导出能力说明（见 [[AI Token-合规与风险控制]]）。

## 横向对比与统一行动策略

| 维度 | Dify | Coze | FastGPT | n8n | RAGFlow |
|---|---|---|---|---|---|
| 私有化 | Docker | 开源版可 | Docker | Docker | 可分布式 |
| 消耗特征 | 视应用形态 | — | 高输入低输出 | 高频小额 | 高输入、高单价 |
| 可预测性 | 中 | — | 高 | 最高 | 中 |
| 我们能否接入 | 能 | 仅开源版 | 能 | 能 | 能 |
| 主要切入点 | 成本归因 | 私有化转折点 | 缓存优化 | 异常防护 | 合规与私有化 |

统一策略：用"逐个应用切换"降低客户决策风险（先切一个应用跑一周看账单）；成本归因（按应用/流程拆分账单）是这一层最普适的价值主张；Embedding 与 Rerank 支持是硬门槛（五个平台里四个涉及 RAG，通道只有对话模型就进不去这一层）；合规材料包必须标准化，一次性发出比客户问一样给一样专业；把这一层作为销售资源第一优先级——量大、服务强度可控、愿意为增值服务付费。
