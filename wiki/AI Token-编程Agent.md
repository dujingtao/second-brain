# AI Token-编程Agent

[[AI Token 业务]]知识库模块 16，覆盖 Claude Code、Cursor、Cline、Roo Code。这是当下 token 消耗最猛、增长最快、也最容易失控的一层——Uber 向 5000 名工程师开放 AI 编程工具后四个月烧光全年预算，米哈游一位工程师做多 Agent 协作测试 13 小时产生 200 万元账单，都出自这一层（见 [[AI Token-行业与Token经济]]）。

如果只能选一层深入，应该选这一层：量最大（一个 50 人研发团队月消耗轻松过十亿）、最不可预测因此最需要管理、客户最痛（研发负责人答不上 CFO"这个月 AI 花了多少"）。核心销售认知是：面对这一层客户，不要卖 token，卖"预算可控"——价格在决策权重里排不进前三。

## 为什么这么烧钱：Agent 循环机制

根本原因是 Agent 循环，不是调用次数。传统代码补全是一次输入一次输出；编程 Agent 的工作方式是读取项目文件→思考→修改代码→跑测试→看报错→再思考……每一轮都是完整的模型调用，且每轮输入都累积着前面所有轮次的上下文。由此产生三个消耗特征：上下文单调增长（任务做到第 20 轮时单次输入可能是第 1 轮的十几倍）；代码库读取是巨量输入（且在同一会话内高度重复，是缓存优化的黄金地带）；失败重试是纯浪费（卡住的任务可能循环十几次没有进展）。销售可以直接问客户"这三块各占多少你们能看到吗"，这是极具杀伤力的开场问题。

## Claude Code

Anthropic 官方终端编程 Agent，能读写文件、执行命令、跑测试、提交 git，形态是终端而非 IDE 插件，因此更容易被写进自动化脚本和 CI 流程，产生无人值守的大量消耗。

接入走 **Anthropic 原生协议**，不是 OpenAI 兼容协议——这是最容易出错的地方。推荐方式是设置环境变量 `ANTHROPIC_BASE_URL`（指向 `.../anthropic`，**不带 `/v1`**，填成 `/v1` 会直接 404）和 `ANTHROPIC_AUTH_TOKEN`（不是 `ANTHROPIC_API_KEY`，填错会 401）；也可写进全局配置文件 `~/.claude/settings.json`。转译方案（中间件把 Anthropic 协议转成 OpenAI 协议）在 tool use、思考过程透传、流式输出上都会出问题，表现为"能聊天但不能干活"，原生协议支持是我们最硬的差异化卖点之一。

这一层里消耗最猛的客户端：默认读取项目上下文、多轮自主执行、常用于大型重构。销售必须主动提示——没配预算熔断的用户，第一个月账单超预期三五倍是常见情况，开户即配熔断是留住客户的关键动作。典型客户是专业开发者和技术驱动创业公司，切入点包括协议原生支持、无人值守场景的熔断需求、以及缓存优化。

## Cursor

以 AI 为核心重构的代码编辑器（VS Code 分支），编程 Agent 里商业化最成功、用户基数最大，自带订阅制同时允许配置自定义 API。

接入走 **OpenAI 兼容协议，base_url 必须带 `/v1`**——正好与 Claude Code 相反，技术支持要能立刻区分。模型 ID 可能需要厂商前缀（如 `anthropic/claude-...`），需要在文档里写死并让客户从控制台复制。注意 Tab 自动补全功能独立于自定义 API 配置，即使接了我们的 API，Tab 补全仍可能走 Cursor 自己的服务，销售不应承诺"所有功能都走我们通道"。

切入点是订阅额度焦虑：只对明确遇到额度瓶颈的重度用户和团队推销，硬推轻度用户会显得不专业，因为对他们而言订阅制通常更划算。

## Cline

VS Code 里的开源终端 Agent 插件，以"免费实现 Cursor 级体验"著称，不做订阅、纯粹按用户自带 API 计费——这意味着它的用户天然是我们的目标客户。

特殊之处是两种协议都支持：OpenAI 兼容模式（Base URL 带 `/v1`）和 Anthropic 原生模式（Base URL 指向 `/anthropic`）。客户主要用 Claude 系模型建议走 Anthropic 原生模式，需要多厂商切换则走 OpenAI 兼容模式。

Cline 的消耗在同类工具里偏高（公开讨论指出其单次请求费用与 Cursor 有数倍差距），原因是默认塞入更多项目上下文且循环轮次多。这对我们是双刃剑——收入高但客户容易被账单吓到，必须首月主动做成本复盘，否则客户会把"贵"归因到我们的价格而非工具本身的消耗方式。因为客户必须自带 Key，决策链最短、销售阻力最低，核心比拼是价格、模型齐全度、稳定性和文档质量。

## Roo Code

从 Cline 分叉出来的开源项目（早期名 Roo Cline），强化了模式/角色系统——可为不同任务（架构师、编码者、调试者等）配置不同角色，各自有独立提示词和工具集。

模式系统直接影响消耗结构，是高价值的优化咨询场景：帮客户设计"哪些任务用轻量模式、哪些必须上旗舰模型"的策略，是典型的"用专业知识换毛利"增值服务（见 [[AI Token-定价体系与单位经济模型]]）。Roo Code 可以为不同模式指定不同模型，一个 Key 就能在所有模式里切换不同厂商模型——这是单一厂商官方 API 做不到的，是对这类用户最有力的销售论点。

## 横向对比与统一行动策略

| 维度 | Claude Code | Cursor | Cline | Roo Code |
|---|---|---|---|---|
| 形态 | 终端 | 独立编辑器 | VS Code 插件 | VS Code 插件 |
| 协议 | Anthropic 原生 | OpenAI 兼容 | 两者皆可 | OpenAI 兼容为主 |
| base_url 带 /v1 | 否 | 是 | 视模式 | 是 |
| 消耗量级 | 极高 | 高 | 高（偏高） | 高，可优化 |
| 销售阻力 | 中 | 中高 | 低 | 低 |

统一策略：把"预算失控"作为统一切入点而非价格；开户即主动配好预算上限、熔断和告警，不等客户要求（第一张账单的震惊是这一层最主要的流失原因）；首月成本复盘必做，标准检查缓存利用率、失败重试占比、模型分配合理性三项，通常能找出 20%–40% 的优化空间；做面向技术社区的搜索内容；识别"从个人到团队"用量跃迁信号并自动触发销售跟进。
