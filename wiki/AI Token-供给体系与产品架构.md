# AI Token-供给体系与产品架构

[[AI Token 业务]]知识库模块 03，解决的问题是：我们卖的东西具体是什么、技术上怎么实现、怎么交付。销售需要讲清楚产品，技术需要知道建什么，客户成功需要知道怎么交付。

## 供给侧：上游资源体系

与上游的关系按合作深度从浅到深分四种，销售对客介绍时必须准确说明某个模型属于哪一种，说错即虚假宣传：**官方代理/经销关系**（有授权文件、能开正式采购凭证，可对客宣称"官方授权渠道"，是最理想的形态）、**企业级 API 采购**（大额采购官方额度、有专属商务折扣，只能宣称"官方直连通道"，不可称"官方授权代理"）、**云平台转售**（通过阿里云百炼、火山方舟、腾讯云等 MaaS 平台采购，稳定性和资质随云厂商，但模型受限于该平台生态）、**第三方聚合中转**（通过其他聚合平台采购，仅作长尾模型或临时冗余的最后补充选项，绝不作主力通道，因为稳定性和合规性不受我们控制，对客户必须如实标注通道性质）。

评估一个上游是否值得接入，按顺序打分：**稳定性优先于价格**（便宜 15% 但每月掉线两次带来的客户流失损失远超省下的成本，无 SLA 承诺的通道不能作主力）；**价格与折扣结构**要看阶梯规则而非当前折扣，决定规模效应能否兑现；**结算条件**（预付/后付、账期、最低消费、额度有效期、能否退款）直接影响现金流，其谈判价值常超过 3%–5% 的价差；**合规完备度**（模型备案号、算法备案截图、正式合同与增值税专票）缺一项都会在服务企业客户时变成障碍；**技术配套**包括协议标准程度、限流透明度、错误码规范、缓存是否可见可计价。

供给风险有四条铁律：单一上游采购占比不超过 40%（超过则一次政策变动能重创业务）；每个主力模型至少两条通道（主通道故障时分钟级切换备用，哪怕更贵）；预付资金不超过可用现金的规定比例（起步期建议不超过 30%，须与下游回款周期匹配）；与上游谈判必须争取"降价保护条款"（预付额度有效期内官方降价则按新价折算或补差，否则一次上游降价就能把批发业务利润全部抹平，参见 [[AI Token-定价体系与单位经济模型]]）。

## 产品架构：统一 AI 网关

产品的全部设计围绕一句话：让客户觉得自己只对接了一个模型，同时享受所有模型的能力。具体展开为四条原则：**零迁移成本**（客户只改一行 base_url，SDK、代码、协议全不变）、**协议原生兼容**（同时原生支持 OpenAI、Anthropic、Gemini，不做中间件转译，避免延迟和字段丢失）、**成本完全可见**（账单精确到每次调用的输入/输出/缓存命中 token 及各自单价）、**故障对客户透明**（上游波动由网关内部消化）。

功能模块按层划分：**接入层**提供统一 API 端点、三协议原生兼容、流式响应、function calling 与结构化输出透传、多模态输入。**路由层**是产品核心差异化所在，包含故障转移路由、成本优化路由、负载均衡路由、场景指定路由四类策略。**计量层**负责逐次调用 token 精确计量、缓存命中识别与单独计价、实时余额扣减、异常调用检测——这一层的准确性是整个商业模式的信用基础，计量出错等于财务出错。**管控层**面向企业客户，提供子账号体系、部门/项目维度用量归集、预算上限与超额熔断、用量告警、调用审计日志（留存不少于 6 个月，合规硬要求）。**分析层**是从工具走向服务的关键，提供成本构成分析、缓存优化建议、模型替换建议、异常消耗归因。**结算层**处理充值扣费、账单生成导出、发票、代理商分润计算。

SLA 与服务承诺是区别于野生中转站的最直接标志，但承诺什么就必须做到什么。起步期建议梯度：长尾客户尽力而为、不作硬性承诺；付费达一定规模的客户承诺 99.9% 可用性；签约企业客户承诺 99.9%–99.95% 并写入合同，配套故障时长对应的服务费减免。原则是：在自身架构冗余能力达标之前，不要签署高于实际能力的 SLA——起步期最常见的自杀方式就是为拿下大客户签了 99.99%，然后被赔穿。

## 交付形态

面向不同客户有四种交付方式：**自助注册**（面向开发者与中小企业，全流程无人工介入，是长尾客户唯一经济的服务方式）；**商务签约**（面向中大型企业，需求调研到定期用量回顾，周期通常 4–12 周）；**白标输出**（面向下游代理商，提供可自定义品牌的控制台、独立域名与结算体系，参见 [[AI Token-渠道与代理商体系]]）；**私有化对接**（面向有数据合规要求的大客户，网关组件部署在客户侧，仅出站调用经过我们的通道，客户数据不落我们的库，是攻克金融、医疗、政务类客户的必要能力，参见 [[AI Token-客户数据合规边界]]）。

标准接入流程共七步：需求确认与场景梳理 → 模型选型建议与试算 → 测试账号开通与 POC → 压测与稳定性验证 → 正式合同与充值 → 生产环境切换与灰度 → 首月用量复盘与优化建议。第七步最容易被忽略也最有价值——首月复盘给出的成本优化建议（通常能帮客户省下 15%–40%）是决定客户是否长期留下的关键动作，也是把关系从"供应商"升级为"顾问"的唯一机会。

## 技术实现路径建议（0→1 阶段）

起步期不要自研全部组件，合理路径分三阶段：第一阶段基于成熟开源网关快速搭建 MVP，把精力放在计量准确性和账单颗粒度上（这是客户最先感知的差异，也是开源方案做得最差的地方）；第二阶段自研路由层和分析层，这是差异化和数据资产的来源；第三阶段补齐企业管控层和私有化部署能力，用于攻克大客户。

有三件事从第一天就必须做对、后期返工代价极高：计量数据的准确与不可篡改（财务和信任的基础）、调用日志的完整留存（合规硬要求，6 个月起）、账户与额度的资金安全（预付款项数据出错就是直接的资金损失和信任崩塌）。
