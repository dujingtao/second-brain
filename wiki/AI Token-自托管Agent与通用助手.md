# AI Token-自托管Agent与通用助手

[[AI Token 业务]]（SpaceTiD）内部知识库模块 13，覆盖 Hermes Agent、OpenClaw、OpenManus、Manus 四个项目，是 [[AI Token-客户端技术知识库总纲]] 第三层（自托管 Agent）的详细展开。数据采集日 2026-07-27。

这一层的共同特征是长期在线、有持久记忆、能自主循环执行任务，消耗曲线是持续型而非脉冲型，是最值得投入销售资源的形态之一。传统"人问一句模型答一句"的消耗天花板是人的打字速度，自托管 Agent 打破了这个天花板——一次"帮我调研这个市场"的指令背后可能是几十次搜索、上百次页面解析、几十轮自我反思，消耗几十万到几百万 token。对公司的直接意义：这一层客户的用量增长不靠他多招人，靠他多派任务，收入随客户业务复杂度增长而非人头增长，是最好的客户结构。同时也是风险最高的一层——循环失控真实存在，一个写坏的定时任务可能一夜烧掉一个月预算，所有这层客户开户时必须强制配置预算熔断（见 [[AI Token-客户端技术知识库总纲]]）。

## Hermes Agent

Nous Research 开发的开源自托管 AI Agent，MIT 协议，自我定位是"住在你服务器上、会记住学过的东西、运行越久越强"的个人代理，不是编程助手也不是聊天机器人。GitHub 约 18 万 Star 量级，2026 年发布桌面版客户端（含 Windows 离线便携包），此前是纯服务端形态，中文社区活跃度较高。它和同层其他项目最大的差异是记忆与技能的持久化——多数 Agent 的生命周期是"一次对话"，Hermes 的生命周期是"这台服务器的寿命"。

核心机制：三层记忆架构（项目记忆保留用户偏好与项目上下文、技能自学在解决复杂问题后自动生成可复用技能文档、数据落本地 `~/.hermes/` 不上传云端）；内置 40 多个技能且能无限自生成（意味着同一客户用得越久，单任务消耗可能下降但任务频次上升，总量通常仍是净增长）；执行沙箱支持 Docker/SSH 远程/Modal/HPC；并行子代理框架允许一个主任务分裂出多个子 Agent 并行工作（这是 token 消耗放大的主要来源，也是成本分析首先要看的地方）；多平台网关接入 Telegram、Discord、Slack、WhatsApp、Signal 及 Cron 定时调度。

部署方式自托管，支持 Linux/macOS/WSL2（Windows 原生为实验性），单行 curl 命令安装，可注册为 systemd 服务常驻。部署门槛不算低但不需要专职运维，典型客户是有自己云服务器、技术背景不错的个人或小团队。

**接入网关**：官方支持 Nous Portal、OpenRouter、自定义 OpenAI 兼容端点、本地 vLLM 四类 Provider，公司走第三条——在 `~/.hermes/` 配置里选自定义 Provider，填 `base_url: https://api.域名/v1`、`api_key`、`model`（完整模型 ID）。销售话术：Hermes 默认推 OpenRouter 是海外通道，国内延迟和稳定性不理想且账单拆不到具体任务，换成公司端点只改三行配置，模型全还能看每个任务烧了多少。

token 消耗是持续型叠加定时任务脉冲，三个放大点值得重点关注（也是极好的优化服务切入口）：子代理并行度、记忆检索的上下文长度（随使用时间增长会悄悄线性上涨）、技能自生成过程本身是高消耗推理。

客户画像：有技术能力的独立开发者、小型技术团队，用量中等偏上、增长稳定、粘性极强（记忆和技能沉淀在本地，迁移成本高）。三个切入点：稳定性（常驻 Agent 最怕半夜定时任务因限流全灭，是多通道自动切换的最佳场景）、成本可见性（Hermes 自己不做成本归集，分账单是刚需）、数据不出境（Hermes 核心卖点是隐私，这类用户对通道走向天然敏感，公司的国内直连+日志留存说明正好对上）。

风险提示：并行子代理可能瞬间打满限流，开户时要评估并发需求；长期运行+记忆增长会导致三到六个月后成本显著高于初期，要在首月复盘时提前告知客户。

## OpenClaw

2026 年 1 月出现的开源个人 AI 助手，作者是 PSPDFKit 创始人 Peter Steinberger，最初是"周末项目"，走红速度罕见：72 小时内 Star 从 1 万涨到 6 万，两天破 10 万，到 2026 年 2 月超过 18.6 万 Star、3.2 万 Fork，是用户基数最大的自托管 Agent。改名历史需要销售知道：最初叫 Clawdbot（取 Claude+claw 之意），因 Anthropic 商标异议改名 Moltbot，最终定名 OpenClaw 强调开源属性——客户说这三个名字中任何一个指的都是同一个东西。

设计理念是把 AI 从"会说"变成"会做"，解决模型被困在浏览器里、用户需要系统级自动化操作（操作系统、访问网页、处理邮件、整理文件、自动写代码）的问题。核心组件：本地算力+大模型驱动的 Agent 自动化、网关服务（默认端口 18789）、带长期记忆的 Workspace 系统、Skills 插件生态（已超 1,700 个插件，是它的护城河，有评论类比为"App Store 之后的 iPhone"）、多渠道消息接入（WhatsApp、Telegram、Discord、iMessage、Slack）。

部署方式支持单命令安装（`curl -fsSL https://openclaw.ai/install.sh | bash`）、npm/pnpm 全局安装、Docker、云厂商一键部署（阿里云腾讯云均有）、源码安装。已知短板（多篇评测反复提到，应如实告知而非回避）：对非技术用户部署门槛偏高、权限管理机制不够完善、插件生态质量参差不齐。

**接入网关**：支持模型面很宽（Claude、Gemini、OpenAI、Ollama、Pi、Qwen、MiniMax、GLM 等），配置方式是环境变量+`~/.openclaw/openclaw.json`组合，走 Claude 系模型用 Anthropic 原生端点，走其他模型用 OpenAI 兼容端点。这类客户以非重度技术用户为主，接入文档写得清不清楚直接决定转化率，建议单独出带截图的接入指南。

token 消耗是脉冲型+长尾型叠加，单次任务消耗从几万到上百万不等，Skills 是消耗的主要变量——插件生态质量参差不齐，存在大量写得浪费的插件，是成本优化最容易出成绩的地方。

客户画像极其广泛，从技术爱好者到中小企业主。这一层商业逻辑不同：单客户价值不高但基数极大，应用极度自助化的方式服务（好的接入文档+顺畅自助注册+小额起充，胜过任何销售动作）。三个切入点：国内可用性（默认接海外模型通道，国内用户体验差，公司提供国内直连+国产模型）、内容营销（18 万 Star 社区活跃项目，接入教程/成本优化指南/模型选型对比的自然流量可观）、从个人用户中筛出企业线索（不少企业技术人员先在个人电脑玩 OpenClaw，再把 AI 引入公司）。

风险提示：权限管理机制不完善是公开承认的短板，能操作系统读写文件访问网络，客户接到生产环境又没做好隔离是真实风险——文档应提示沙箱隔离，但这是客户侧责任，公司不能因为通道由自己提供就承担连带责任；插件生态未经审核，不背书任何具体插件；用户以非重度技术人员为主，技术支持负荷偏高，必须靠文档和 FAQ 压成本，不能靠人力。

## OpenManus

Manus 的开源复现项目，由 MetaGPT 团队相关开发者发起，以"三小时复刻 Manus"闻名，迅速获得 2 万以上 Star。价值不在功能完整度追平 Manus（做不到），而在于把通用 Agent 架构讲透了——初始版本约 30 个核心文件，代码精简，是理解 Agent 框架设计的最佳教材。

架构是四层继承：BaseAgent（基础属性：名称、记忆、系统提示词）→ ReActAgent（Reasoning+Acting 循环）→ ToolCallAgent（细化工具选择与执行）→ Manus（配定制提示词与工具集）。关键机制是 ReAct 循环：思考→选工具→执行→观察结果→再思考，每一轮都是一次完整模型调用且上下文累积前面所有轮次内容——**这是 Agent 类应用 token 消耗呈非线性增长的根本原因：不是调用次数多，是每次调用的上下文都在变长**。这段话术可以直接讲给客户听，讲清楚之后"缓存优化"和"上下文压缩"的价值不言自明。核心工具集：PythonExecute、BrowserUseTool、GoogleSearch、FileSaver、PlanningTool。

部署是标准 Python 项目（conda/venv + pip install），模型配置集中在 `config/config.toml`，核心字段是 `[llm]` 下的 `model`、`base_url: https://api.域名/v1`、`api_key`、`max_tokens`、`temperature`——配置极简，是所有项目里接入最顺的之一，销售可以在电话里口述完成。

token 消耗特征是典型 Agent 循环消耗，且作为教学型项目在上下文管理和缓存利用上比较朴素，同样任务消耗通常高于成熟商业 Agent（对公司是好事，但要提前提示客户避免第一张账单吓到他）。

客户画像：AI 应用创业公司技术团队、想自研 Agent 的企业研发部门、高校与研究机构，真正价值不在他们跑 OpenManus 本身烧的 token，而在于大概率正在做二次开发，做出来的东西才是真正用量来源。切入点是把他们当"未来的大客户"服务——demo 阶段就给足测试额度和技术支持，产品上线后自然是默认通道，获客成本低、生命周期价值高。特别提示：这类客户属于 [[AI Token-合规与风险控制]] 定义的"二次开发"范畴，合规义务按自研模型标准执行，销售应主动提示这一点。

风险提示：项目定位是教学与复现不是生产就绪，不要暗示可直接上生产；中文互联网资料版本混杂，部分早期文章配置方式已过时，技术支持应以官方仓库 README 为准。

## Manus

蝴蝶效应公司（Butterfly Effect）推出的通用 AI Agent，对外宣称"全球首款自主通用 AI Agent"，是商业闭源产品，不是开源项目——这一点决定了它在公司业务里的位置与前三者完全不同。

架构与能力：多智能体并行处理（分布式任务处理绕开单一上下文窗口限制）、虚拟机沙箱（隔离环境+浏览器自动化，能像真人一样操作电脑）、Manus 1.6 引入 Max Agent 强化规划架构。典型场景包括设计创作、市场调研、学术研究、批量内容生产、数据抓取，可与 Gmail、Notion、Zapier 等集成。

定价是订阅+积分双轨制：Basic $20/月（每月 4,000 积分）、Standard $40/月（8,000 积分）、Professional $200/月（40,000 积分），三档每日刷新 300 积分，均含 20 个并发任务和 20 个定时自动化。

**它对公司的意义**：这是本模块唯一一个卖不进去的项目（闭源 SaaS，客户用它就是买它的积分，公司无法成为其上游），但恰恰是最有销售价值的一个：第一，它是最好的价值锚点——客户在用 Manus Professional 说明已认可"让 AI 自主干活"的价值且愿意付费，是极强的购买意愿信号，"你们在用 Manus 吗"应成为销售的常规问题；第二，它是最好的成本对比素材——积分制不透明，客户不知道钱花在哪，而 token 计费完全透明，可以借此话术引导客户对比自建方案（如用 OpenManus 或 Hermes 自建、模型走公司通道）的成本可见性；第三，它定义了客户对 Agent 能力的期待，公司若建议客户自建，必须诚实说明开箱即用程度上的差距，不能为了成单夸大开源方案的成熟度。

风险提示：不要把 Manus 当竞争对手攻击，它是应用而公司是基础设施，不在同一层，正确姿态是认可其产品力、讨论其成本透明度；积分与 token 之间没有公开换算关系，任何"比 Manus 便宜多少倍"的量化宣称不可验证，不能写进对外材料，只能引导客户自己算。

## 横向对比与销售策略

| 维度 | Hermes Agent | OpenClaw | OpenManus | Manus |
|---|---|---|---|---|
| 性质 | 开源 MIT | 开源 | 开源 | 商业闭源 |
| 部署 | 自托管服务器 | 自托管/本地 | 本地 Python | SaaS |
| 核心特色 | 持久记忆+技能自学 | Skills 生态+多渠道 | 架构清晰、教学价值 | 开箱即用、沙箱 |
| 用户量级 | 大 | 极大 | 中 | 中（付费） |
| 能否接入网关 | 可 | 可 | 可 | 不可 |
| 单客户价值 | 中高 | 低（基数大） | 低（转化潜力高） | — |
| 服务方式 | 半自助+轻支持 | 纯自助+文档 | 轻销售+培育 | 作为线索来源 |

一句话销售策略：OpenClaw 用内容和文档收长尾，Hermes 用稳定性和成本可见性做中坚，OpenManus 当未来大客户培育，Manus 用户当高意愿线索来挖。
