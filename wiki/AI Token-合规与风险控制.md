# AI Token 合规与风险控制

[[AI Token 业务]]（SpaceTiD）的知识库把合规定位为这门生意的第一优先级，而不是一项成本。市场上有大量"野生"API 中转站靠低价和灵活性生存，但普遍缺资质、无法开票、不做日志留存、不提供备案信息；随着监管要求在 2026 年落地咬合，这批玩家会被逐步清退出企业级市场。这意味着把合规做扎实，等于自动获得一批竞争对手进不去的市场（需要过内审、外审、供应商准入的企业客户）；反之合规不扎实，不是慢慢被淘汰，而是可能一次出事就结束——商业风险是渐进可修补的，合规风险是断崖式、不可逆的。

## 转售授权：业务合法性的前提（重点风险）

**阿里、腾讯、智谱的服务协议均明确禁止未经书面许可的转售**：智谱用户协议七条 3 款、GLM Coding Plan 团队套餐协议六条 2 款直接点名"转售、代售、转包装、聚合转发"；腾讯混元协议 2.6(6) 条直接点名"API Token"；阿里云百炼协议 4.6 条同样明确禁止。这不是可以事后补救的细节，而是知识库中记录的一次重大认知修正（详见 [[AI Token-客户数据合规边界]] 第九节）：早先"转售上游 API 在法律上是干净的"这一判断已被证伪，正确结论是**官方渠道/经销的书面授权不是锦上添花的信任背书，而是渠道代理与批发分销这两条业务线合法存在的前提**——没有它，相关业务线在协议层面处于违约状态。签约与商务谈判前必须先确认拿到书面授权，销售和决策层在与上游谈判时必须把这一条当作前置条件，而不是走完流程后才发现的问题。

## 法规框架与备案要求

核心法规是 2023 年 8 月 15 日起施行的《生成式人工智能服务管理暂行办法》，配套有《生成式人工智能服务安全基本要求》、《互联网信息服务算法推荐管理规定》及相关算法备案与安全评估要求，国家网信办定期公告已备案的生成式人工智能服务信息。

一个关键的实操区分是**"纯 API 调用"与"二次开发"**：仅调用第三方已备案模型能力、不改写输出逻辑、不做自定义封装或提示词工程深度改造、不做再训练，属于纯调用，通常只需完成属地登记并公示备案信息，无需按自研模型标准办国家级备案；一旦对输出逻辑改写、做自定义封装、做提示词工程优化或再训练，就要按自研模型标准办理国家级备案。这直接影响产品设计边界——网关如果只做通道透传、路由和计量属于纯调用范畴，但如果开始提供"优化后的 prompt 模板""场景化封装"等能力，就可能落入二次开发范畴、合规义务显著加重。业务纪律是任何涉及输出逻辑改写的新功能上线前必须先做合规评估，不能技术先上线合规后补。

**自 2026 年起的硬性要求**：通过 API 调用第三方大模型面向公众提供服务的应用，必须在显著位置（首页底部、服务协议页或"关于我们"，字体不小于正文常规字号，不得遮挡折叠）公示模型名称、国家网信办备案号、属地登记编号三项信息。这对公司是双重意义：自己的平台必须做到，同时也是极好的销售切入点——很多客户还不知道这个要求，主动告知并提供所需备案文件是建立专业形象最快的方式（详见 [[AI Token-销售方法论与话术库]]）。

材料留存方面必须完整保存 API 服务协议、模型备案文件、接口调用日志（不少于 6 个月）、内容审核记录；6 个月日志留存是硬性技术要求，必须在产品架构设计阶段就考虑存储成本，不是可选项也不能事后补。

面向公众提供服务的应用合规义务完整适用，仅面向企业内部使用的应用监管义务相对较轻但仍需满足数据安全合规要求——销售必须问清客户的服务对象，问错了会给客户带来实际风险。此外，具有舆论属性或社会动员能力的服务（内容生成、社交、资讯类客户常落入此类）需额外完成安全评估并提交自评估报告，销售识别到这类客户应主动提示其合规义务。

## 经营资质清单

基础资质是营业执照（经营范围覆盖软件和信息技术服务、技术推广等）和 ICP 备案；对外提供在线服务并收费的平台通常还需要增值电信业务经营许可证（ICP 或 EDI 许可证，具体取决于业务形态定性）；生成式人工智能服务相关备案/登记按上述"纯调用"与"二次开发"区分确定义务范围；服务金融、医疗、政务类企业客户通常还需信息安全等级保护测评；此外可能有目标行业的额外资质要求。资质办理周期长（部分需数月），建议在 0→1 阶段就把基础资质和 ICP/EDI 排上日程，等保测评在首个企业客户进入商务流程时同步启动，不能等客户要求时才办。

## 内容与用途风控

所有客户（包括代理商的终端客户）开通正式服务前必须完成主体身份核验（企业营业执照、个人实名）、用途声明、以及高风险用途的额外审核。明确拒绝服务的用途包括违法违规内容生成与分发、诈骗与虚假信息制作、侵犯他人合法权益、以及任何要求协助规避监管义务的需求；销售识别到明显违规用途要直接拒绝，不上报不犹豫不为业绩变通。

产品层面需具备异常调用模式的自动识别（超高频调用、批量违规内容特征）、可疑账号的自动限制与人工复核、以及真实可用、响应以分钟计的紧急切断能力——出事时监管部门不会等内部走流程。

代理商的连带风险是渠道体系最危险的一环：代理商可能把通道卖给违规客户，责任会追溯到通道提供方（这与前述转售授权风险是这门生意里最核心的两类法律暴露）。管控要求是代理协议中明确代理商对终端客户的核验义务与连带责任、我方保留对所有下级账号的监控权与切断权、终端客户实名信息必须可追溯到具体主体，不允许"代理商批量开号、终端客户不可见"（详见 [[AI Token-渠道与代理商体系]]）。

## 其他关键风险

**数据安全**：最小化留存原则——调用日志按合规要求留存元数据（时间、模型、token 数、账号），内容本身除非客户明确要求否则不做长期存储，存储数据需加密并有权限控制和审计记录；涉及个人信息处理需遵守《个人信息保护法》，为有此类需求的客户提供私有化部署（网关组件部署客户侧，数据不落己方库）是最稳妥的解法。

**资金风险**：客户预充值形成的资金属于预收账款，必须与运营资金分账管理，不得挪用——挪用预付款是最快的死法，一旦兑付困难就是刑事风险；上游预付风险的核心是降价保护条款、周转周期控制和资金上限（详见 [[AI Token-定价体系与单位经济模型]]）；坏账风险方面账期客户必须有授信额度上限、超期自动停供，单一客户应收不超过总应收的 25%。

**SLA 赔付风险**：签署的 SLA 必须与实际架构能力匹配，赔付条款要设单次和年度上限（常见做法是以当期服务费为上限），避免一次故障造成不可承受的损失。

**上游依赖风险**：任何单一上游采购占比不超过 40%，每个主力模型至少两条通道（详见 [[AI Token-供给体系与产品架构]]），与上游合同中还需关注单方终止通知期、价格调整提前告知义务、已购额度的处理方式。

## 合规自查清单（建议按月）

平台是否已公示所调用模型的名称、备案号与属地登记编号；调用日志留存是否满足 6 个月且可完整导出；所有客户是否完成主体核验与用途声明；是否存在未经审核的高风险用途客户；紧急切断能力是否经过实际演练；客户预付款是否与运营资金分账；单一上游采购占比是否超过 40%；单一客户收入占比是否超过 15%；代理商的终端客户是否全部可追溯到实名主体；已签署的 SLA 是否均在架构实际能力范围内；新上线功能是否均已完成合规评估。任何一项为"否"都需限期整改。

以上内容为业务理解与自查用，不构成法律意见，具体合规方案需咨询专业律师及当地网信、通管部门。
